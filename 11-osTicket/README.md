# Шаг 11. Тикет-система osTicket

## Цель

Развернуть реальную систему Service Desk, отработать полный цикл обработки тикетов: от создания заявки пользователем до её решения и закрытия агентом.

## Что такое osTicket

**osTicket** — бесплатная open-source система Service Desk, которую используют в реальных компаниях для обработки обращений пользователей. Это **не симуляция**, а рабочая система — то же самое, что ServiceNow, Jira Service Desk или GLPI.

## Что сделано

### 1. Развёртывание

osTicket установлен на Windows Server 2019 как веб-приложение:

- **Веб-сервер:** IIS + URL Rewrite
- **PHP:** 8.2.34 (FastCGI)
- **База данных:** MySQL 8.0
- **URL портала:** `http://192.168.1.10/osTicket/`
- **URL панели агента:** `http://192.168.1.10/osTicket/scp/`

### 2. Настройка прав

- **NTFS-права** на папке osTicket настроены для пула приложений IIS (`IIS AppPool\DefaultAppPool`) и пользователя `IUSR`.
- **`ost-config.php`** — только чтение (после установки).
- Папка `setup` удалена.

### 3. Обработанные тикеты

Смоделировал и обработал **10 типовых инцидентов L1**:

| # | Тема | Приоритет |
|---|------|-----------|
| 1 | Забыл пароль | High |
| 2 | Учётка заблокирована | High |
| 3 | Нет доступа к папке HR | Medium |
| 4 | Не работает интернет | High |
| 5 | Медленно работает ПК | Low |
| 6 | Не открывается панель управления | Low |
| 7 | Пропал сетевой диск S: | Medium |
| 8 | Принтер не печатает | Medium |
| 9 | Почта не отправляется | High |
| 10 | Экран мерцает | Low |

### 4. Полный цикл обработки

Для каждого тикета:

1. **Пользователь** создаёт заявку через портал.
2. **Агент** открывает тикет в панели → устанавливает **Priority**, **Department**, **Assigned To**.
3. **Внутренняя заметка (Internal Note)** — диагностика и план действий.
4. **Ответ пользователю (Response)** — вежливое сообщение с решением.
5. **Ticket Status → Resolved** — тикет закрыт.

### 5. Работа с приоритетами

Настроена сортировка по приоритету:

- **High** — блокирующие проблемы (пароль, интернет, почта).
- **Medium** — частично блокирующие (доступ к папке, принтер).
- **Low** — неудобства без блокировки (медленный ПК, мерцание).

## Ключевые выводы

- **osTicket ≠ симуляция.** Это реальная система, которую используют компании. Работа с ней показывает работодателю, что ты **готов с первого дня** сесть за рабочую тикет-систему.
- **Полный цикл тикета:** создание → назначение → диагностика → ответ → закрытие.
- **Internal Note vs Response:** внутренние заметки **не видит** пользователь — они для команды поддержки.
- **Приоритеты** — базовый навык L1. High/Medium/Low определяется по **влиянию на бизнес**.
- **SLA** — на каждый тикет автоматически назначается срок реакции (Default SLA).
