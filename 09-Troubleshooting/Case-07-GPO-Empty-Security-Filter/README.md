# Case 07. GPO не применяется — пустой фильтр безопасности

## Ситуация

У пользователя **User4 (отдел Sales)** пропали корпоративные обои — на рабочем столе **чёрный экран**. При этом:
- Шара `\\192.168.1.10\Wallpapers` **доступна** с клиента.
- Файл `wallpaper.jpg` **есть** на сервере.
- GPO `Sales_Desktop_Policy` **создан** и **привязан** к OU Sales.

- **Тип проблемы:** Group Policy
- **Клиент:** User4 (Sales)
- **GPO:** `Sales_Desktop_Policy`

## Диагностика

### 1. Проверка шары с клиента

```cmd
dir \\192.168.1.10\Wallpapers
```

Файл `wallpaper.jpg` **виден** — шара работает, права настроены.

**Вывод:** проблема **не в файле и не в шаре**.

### 2. Проверка GPO на сервере

В **GPMC**:
- GPO `Sales_Desktop_Policy` **существует**.
- Привязан к **OU Sales** и **OU Workstations**.
- Фильтры безопасности — **пусты**.

### 3. Проверка применения GPO на клиенте

```cmd
gpresult /r
```

В разделе **«Следующие политики GPO не были применены»**:

```
Sales_Desktop_Policy
    Фильтрация: Не применено (причина неизвестна)
```

**Вывод:** GPO **не применяется** к пользователю.

### 4. Ключевая причина

В **GPO → вкладка «Область» → раздел «Фильтры безопасности»** — **пусто**. То есть **ни одна группа** не имеет права применять этот GPO.

**Почему возник симптом «чёрный экран», а не «стандартные обои Windows»:**

Windows сохраняет **кэш применённых политик**. Политика **была применена ранее** (до того, как фильтр опустел) — поэтому Windows **помнит**, что должно быть **корпоративное обои**. Но **загрузить файл не может** (GPO отфильтрован) → отображает **чёрный фон**.

Если бы политика **никогда не применялась** — были бы **стандартные обои Windows** (синий фон).

## Решение

### 1. Добавить группу в фильтр безопасности

1. **GPMC** → `Sales_Desktop_Policy` → вкладка **«Область»**.
2. Раздел **«Фильтры безопасности»** → **«Добавить…»**.
3. Ввести: **`Прошедшие проверку`** (Authenticated Users).
4. **«Проверить имена»** → **ОК**.

### 2. Проверить делегирование (вкладка «Делегирование»)

Убедиться, что у **`Прошедшие проверку`** есть права:
- **Read**
- **Apply Group Policy**

Если нет — добавить через **«Дополнительно»**.

### 3. Применить GPO на клиенте

```cmd
gpupdate /force
```

Затем **logoff → login** (для пользовательских GPO — нужен именно **вход пользователя**, не перезагрузка).

### 4. Проверка

```cmd
gpresult /r
```

В разделе **«Применённые объекты групповой политики»** появился `Sales_Desktop_Policy`.

**Результат:** обои **вернулись** на рабочий стол.

## Ключевые выводы

### Для специалиста L1

- **`gpresult /r`** — первый инструмент при проблемах с GPO. Показывает, **какие политики применены**, а какие — **нет**.
- **«Фильтрация: не применено»** — намёк на **проблему с правами** (Security Filtering или Delegation).
- **Фильтр безопасности GPO** — критичен. Если пуст — GPO **не работает ни для кого**, даже если привязан к OU.
- **`Прошедшие проверку`** (Authenticated Users) — **стандартная** группа, добавляется при создании GPO автоматически. Если её убрали — GPO «отвалится» для всех.
- **Чёрный экран vs стандартные обои:** чёрный экран = **политика применилась когда-то**, но **сейчас не активна**. Стандартные обои = **политика никогда не применялась**.
- **`Local Group Policy` в разделе «не применено»** — это **норма**. Она пуста по умолчанию, потому что на этом ПК нет локальных настроек.

### Почему так произошло

**Возможные причины:**
- **Случайное удаление** `Authenticated Users` из фильтра при настройке GPO.
- **Изменение Delegation** — убрано `Apply Group Policy` у `Authenticated Users`.
- **WMI-фильтр** — если настроен и не проходит на клиенте.

### Что проверять, если GPO не применяется

1. **Привязан ли GPO** к нужному OU (Scope → Links).
2. **Включена ли связь** (Link Enabled = Yes).
3. **Фильтр безопасности** — есть ли группы, к которым должен применяться GPO.
4. **Delegation** — есть ли права `Read` + `Apply Group Policy` у нужных групп.
5. **WMI-фильтр** — если есть, проверить его условия.
6. **`gpresult /r`** на клиенте — какие GPO **должны** применяться, какие **не применяются** и **почему**.
