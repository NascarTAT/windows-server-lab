# Case 04. Удаление A-записи контроллера домена в DNS



## Ситуация



Клиент сообщает: **не может подключиться к серверу по имени**. Программы и сетевые ресурсы, использующие имя сервера (`\\WIN-SKIC7TCTV5T\...`), не работают.



- **Тип проблемы:** DNS / Name Resolution

- **Клиент:** User3 (HR)

- **Компьютер клиента:** DESKTOP-UJAHLGC

- **Затронутый ресурс:** A-запись контроллера домена в зоне `lab.local`



## Диагностика



### 1. Проверка доступности сервера



На клиенте:



```cmd

ping WIN-SKIC7TCTV5T

```



**Результат:** «Не удалось обнаружить узел WIN-SKIC7TCTV5T».



```cmd

ping 192.168.1.10

```



**Результат:** 4 пакета отправлено, 4 получено, 0% потерь.



**Ключевой вывод:** сервер **доступен по IP**, но **не резолвится по имени**. Проблема **не в сети**, а в **DNS**.



### 2. Проверка службы DNS на сервере



```powershell

Get-Service -Name DNS

```



**Результат:** `DNS — Running`. Служба **работает**.



### 3. Проверка A-записей в зоне lab.local



В **оснастке DNS** (Server Manager → Средства → DNS) → **Зоны прямого просмотра** → **lab.local** — **A-запись сервера `win-skic7tctv5t` отсутствовала**.



### 4. Поиск причины в логах DNS



В **Event Viewer** → **Журналы приложений и служб** → **Microsoft** → **Windows** → **DNS-Server** → **Audit**.



**Найдено событие ID 517:**



> «Все записи ресурса типа 1 с именем WIN-SKIC7TCTV5T.lab.local удалены из области Default зоны lab.local».



**Причина подтверждена:** A-запись контроллера домена была удалена из зоны.



## Решение



### 1. Принудительная перерегистрация DNS-записей



На сервере:



```cmd

ipconfig /registerdns

```



Команда запускает **повторную регистрацию** всех DNS-записей компьютера. Отчёт об ошибках появится в Event Viewer через 15 минут.



### 2. Перезапуск службы Netlogon



```cmd

net stop netlogon && net start netlogon

```



**Что делает:** служба **Netlogon** отвечает за регистрацию **SRV-записей** и **A-записи** контроллера домена в DNS. Перезапуск заставляет её **автоматически пересоздать** критически важные записи.



### 3. Проверка с клиента



```cmd

ping WIN-SKIC7TCTV5T

```



**Результат:**

```

Обмен пакетами с win-skic7tctv5t.lab.local [192.168.1.10]:

Ответ от 192.168.1.10: число байт=32 время<1мс TTL=128

...

Потеряно: 0 (0% потерь)

```



Имя снова **резолвится** в IP. Проблема решена.



### 4. Подтверждение в оснастке DNS



После фикса A-запись `win-skic7tctv5t` **восстановлена** в зоне `lab.local` (тип «Узел (A)», значение `192.168.1.10`).



## Причина сбоя



**В рамках учебного кейса:** A-запись контроллера была **вручную удалена** командой:



```powershell

Remove-DnsServerResourceRecord -ZoneName "lab.local" -Name "WIN-SKIC7TCTV5T" -RRType "A" -Force

```



Это **имитация реальной ситуации**, когда запись удаляется случайно (ошибка администратора, сбой репликации, повреждение зоны).



**Что бы я делал в реальной работе для поиска причины:**



1. Проверил бы **журнал DNS-Server → Audit** — там фиксируются все изменения зон (Event ID 517 при удалении).

2. Проверил бы **журнал Directory Service** на контроллере — если репликация между DC нарушена.

3. Сравнил бы зоны **на всех контроллерах домена** — если запись есть на одном и нет на другом, проблема в репликации.

4. Проверил бы **задачи планировщика** и **скрипты** — не удаляют ли они DNS-записи автоматически.

5. Проверил бы **события Netlogon** — если служба падала, записи могли не зарегистрироваться после перезагрузки.



## Ключевые выводы



- **Ping по имени vs ping по IP** — базовый приём диагностики. Если IP работает, а имя нет → **проблема в DNS**.

- **`ipconfig /registerdns`** — принудительная перерегистрация DNS-записей компьютера. Штатный инструмент Windows.

- **Служба Netlogon** — отвечает за регистрацию SRV и A-записей контроллера домена. Перезапуск восстанавливает записи автоматически.

- **Event Viewer** — журналы **конкретных служб** (`DNS-Server`, `Directory Service`) содержат профильные события, которые не попадают в общие логи.

- **Копирование текста ошибки в поиск** — эффективный способ найти решение. Главное — **понимать**, что найдено, и **применять** к своей ситуации.
