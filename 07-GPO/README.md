\# Шаг 7. Групповые политики (GPO)



\## Цель



Освоить централизованное управление настройками пользователей и компьютеров

через групповые политики: привязка GPO к OU, настройка политик и предпочтений,

проверка применения на клиенте.



\## Что сделано



\### 1. GPO для OU Sales — настройка рабочего стола



Создан GPO \*\*`Sales\_Desktop\_Policy`\*\*, привязанный к OU `Sales`.

В нём настроены две политики (User Configuration → Policies):



\- \*\*Обои рабочего стола\*\* — через UNC-путь к сетевой папке

&#x20; `\\\\192.168.1.10\\Wallpapers\\wallpaper.jpg`.

\- \*\*Запрет доступа к панели управления и параметрам компьютера\*\*.



Для файла обоев на сервере создана папка `C:\\Wallpapers` и шара `Wallpapers`

с доступом на чтение для группы «Пользователи домена».



\*\*Проверка:\*\* под учётной записью `User4` (OU Sales):

\- ✅ Обои применились автоматически при входе.

\- ✅ При попытке открыть панель управления появляется сообщение

&#x20; «Операция отменена из-за ограничений, действующих на этом компьютере».



\### 2. GPO для OU HR — подключение сетевого диска



Создан GPO \*\*`HR\_Drive\_Mapping`\*\*, привязанный к OU `HR`.



Настроено \*\*сопоставление диска\*\* через `User Configuration → Preferences`

(не Policies — это важное различие):

\- Буква диска: \*\*`S:`\*\*

\- Путь: `\\\\192.168.1.10\\HR`

\- Действие: \*\*Create\*\*

\- Опция «Подключать заново» (Reconnect) — включена.



На сервере создана папка `C:\\Shares\\HR` и шара `HR`.



\*\*Проверка:\*\* под учётной записью `User3` (OU HR):

\- ✅ Диск `S:` автоматически появился в «Этот компьютер» при входе.



\### 3. Проверка точечности применения



Доказано, что GPO применяются строго по OU:



| Пользователь | OU    | Обои Sales | Запрет панели управления | Диск S: |

|--------------|-------|------------|--------------------------|---------|

| User4        | Sales | ✅ Да      | ✅ Да                    | ❌ Нет  |

| User3        | HR    | ❌ Нет     | ❌ Нет                   | ✅ Да   |



\## Ключевые понятия



\### Policy vs Preference



\- \*\*Политики (Policies)\*\* — принудительные настройки. Их нельзя изменить

&#x20; на клиенте. Применяются через `Administrative Templates`.

&#x20; Примеры: обои, запрет панели управления.

\- \*\*Настройки (Preferences)\*\* — гибкие настройки. Пользователь может

&#x20; их изменить вручную. Применяются через отдельную ветку `Preferences`.

&#x20; Примеры: маппинг диска, ярлыки, принтеры.



\### User Configuration vs Computer Configuration



\- \*\*Конфигурация пользователя\*\* — применяется при входе пользователя.

&#x20; Примеры: обои, маппинг диска, запреты в интерфейсе.

\- \*\*Конфигурация компьютера\*\* — применяется при загрузке компьютера.

&#x20; Примеры: настройки firewall, автозапуск, парольная политика.



\### Обновление политик



\- `gpupdate /force` — принудительно применить политики.

\- Политики пользователя применяются \*\*при входе\*\* — нужен logoff/login.

\- Политики компьютера применяются \*\*при загрузке\*\* — нужна перезагрузка.
